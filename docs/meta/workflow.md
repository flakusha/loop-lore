# Workflow: Issues & Worktrees

Loop Lore tracks planning artifacts directly in the repository using
[git-native-issue](https://github.com/remenoscodes/git-native-issue) and git
worktrees for parallel development. This page documents the integrated flow.

## Issues (git-native-issue)

Issues are stored as orphan commits under `refs/issues/<uuid>` — no external
service required. Each issue carries an **extended identifier** used throughout
the docs and commit trailers:

| Prefix   | Meaning                       |
| -------- | ----------------------------- |
| `BUG-`   | Bug reports                   |
| `FEAT-`  | Feature requests              |
| `FIX-`   | Non-bug fixes                 |
| `IDEA-`  | Research / experimental ideas |
| `TASK-`  | Small tasks                   |
| `SOL-`   | Architectural solutions       |
| `EPIC-`  | Major epics                   |
| `INFRA-` | Infrastructure                |

Identifier format: `<TYPE>-YYYY-<NNN>` (e.g. `BUG-2026-002`, `FEAT-2026-001`).

### Commands

```bash
# List open issues (with branch mapping)
./scripts/worktree.sh issues

# Create an issue + branch + worktree in one step
./scripts/worktree.sh ticket FEAT 015 "Add dark mode toggle"

# Create an issue only
git issue create "Title" -m "Body" -l feature -p medium

# Show / comment / close
git issue show BUG-2026-002
git issue comment BUG-2026-002 -m "Reproduced on Firefox"
git issue state BUG-2026-002 closed
```

The full issue list is published in the docs site at
[Issue Tracker](/meta/issues), regenerated by `bun run docs:gen`.

### Linking issues in docs

Any extended identifier written in a doc (e.g. `EPIC-2026-16`, `FEAT-2026-003`)
is automatically hyperlinked to its entry in the Issue Tracker by the Vitepress
markdown plugin. No manual markup required.

### Commit trailers

Link commits to issues so they are traceable:

```
Issue: BUG-2026-002
Epic: EPIC-2026-16
Status: done
Solution: SOL-2026-001
```

## Worktrees (parallel development)

`scripts/worktree.sh` manages git worktrees so multiple branches can be worked
on simultaneously without stashing.

```bash
# Create a worktree for an existing branch
./scripts/worktree.sh create feat-14-io

# Create a new branch + worktree (base defaults to master)
./scripts/worktree.sh new feat-my-feature

# Create a ticket branch + worktree (issue already created)
./scripts/worktree.sh new ticket/BUG-2026-002 master

# List / clean up
./scripts/worktree.sh list
./scripts/worktree.sh cleanup          # removes worktrees for deleted branches
./scripts/worktree.sh remove feat-x   # blocks if dirty

# Integrate back
./scripts/worktree.sh merge master feat-x     # merge into a branch
./scripts/worktree.sh finalize feat-x         # check → test → GPG-signed merge → remove
```

### GPG signing

Commits made inside worktrees are GPG-signed with the agent key configured in
`.credentials.env`. Use `./scripts/worktree.sh agent-commit <branch> "msg"`
rather than raw `git commit`. Merge/finalize operations sign the resulting
merge commit automatically.

### Branch conventions

| Branch pattern         | Purpose                       |
| ---------------------- | ----------------------------- |
| `ticket/<TYPE>-YYYY-N` | Work for a specific git issue |
| `feat/<name>`          | Feature work                  |
| `fix/<name>`           | Bug fixes                     |
| `epic/<n>`             | Major epic initiative         |

## End-to-end example

```bash
# 1. Create issue + worktree
./scripts/worktree.sh ticket BUG 002 "Browser E2E parallel instability"
#    → issue BUG-2026-002, branch ticket/BUG-2026-002, worktree tree/ticket-BUG-2026-002

# 2. Work in the worktree
cd tree/ticket-BUG-2026-002
# ... edit, test ...

# 3. Commit (GPG-signed)
./scripts/worktree.sh agent-commit ticket-BUG-2026-002 "fix(e2e): isolate cachedSoloUser"

# 4. Merge back to master (GPG-signed merge, worktree removed)
./scripts/worktree.sh finalize ticket-BUG-2026-002
```
