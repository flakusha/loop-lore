# Flexible RPG Patterns Specification

> ⚠️ **Status:** STUB — auto-generated by reconciliation. Needs expansion.
> High-level notes — may drift from implementation. Authoritative source is `src/` and AGENTS.md.

## Overview

Design patterns for making RPG mechanics toggleable, composable, and
world-configable. Ensures mechanics can be disabled per world/setting
without code changes.

## Core Patterns

### Toggle Pattern

Every RPG subsystem is toggleable per world:

```typescript
interface WorldConfig {
  rpg: {
    enabled: boolean;
    dice: boolean;
    combat: boolean;
    crafting: boolean;
    factions: boolean;
    // ... each subsystem independently toggleable
  };
}
```

### Plugin Pattern

RPG subsystems are plugins that register with the core engine:

```typescript
interface RPGPlugin {
  name: string;
  version: string;
  hooks: {
    onTurnStart?: (ctx: TurnContext,) => void;
    onTurnEnd?: (ctx: TurnContext,) => void;
    onAction?: (ctx: ActionContext,) => Result;
    onStateChange?: (ctx: StateContext,) => void;
  };
  schema: ZodSchema; // config schema for this plugin
}
```

### Resolution Chain Pattern

Actions flow through a resolution chain:

1. **Intent extraction** — LLM extracts structured intent
2. **Validation** — engine validates against rules
3. **Resolution** — dice/algorithm resolves outcome
4. **State mutation** — engine applies changes
5. **Narrative generation** — LLM generates story text

### State Machine Pattern

Player/entity states use finite state machines:

```typescript
type PlayerState =
  | { type: "idle" }
  | { type: "in-combat"; encounter: Encounter }
  | { type: "in-dialogue"; npc: NPCId }
  | { type: "crafting"; recipe: RecipeId }
  | { type: "exploring"; location: LocationId };
```

### Effect System Pattern

Temporary and permanent effects stack:

```typescript
interface Effect {
  id: string;
  source: string;
  duration: number | "permanent";
  modifiers: StatModifier[];
  conditions: Condition[];
}
```

### Event-Driven Pattern

Subsystems communicate via events:

```typescript
type RPGEvent =
  | { type: "combat:hit"; attacker: Id; target: Id; damage: number }
  | { type: "craft:complete"; player: Id; item: ItemId }
  | { type: "faction:reputation-change"; faction: Id; delta: number };
```

## Configuration Patterns

### Per-World Overrides

```json
{
  "world": "dark-fantasy",
  "rpg": {
    "dice": { "system": "d20", "critical": 20 },
    "combat": { "lethality": "high", "death-saves": true },
    "crafting": { "discovery": true, "failure-destroy": true },
    "factions": { "enabled": true, "pvp": false }
  }
}
```

### Difficulty Scaling

```typescript
interface DifficultyProfile {
  name: string;
  diceModifier: number;
  enemyScaling: number;
  resourceScarcity: number;
  deathPenalty: "none" | "light" | "heavy" | "permadeath";
}
```

## Anti-Patterns

- ❌ Hardcoded mechanics that can't be disabled
- ❌ Direct LLM state mutation (engine must be source of truth)
- ❌ Tight coupling between subsystems
- ❌ Global state instead of per-world/per-session state
