# EPIC: Unified Spec Framework for `.plan/`

**Status:** 🟡 Design (Phase A) — research + schema proposal complete; tooling to land
**Priority:** High
**Effort:** Large (spread across 4 phases)
**Type:** Meta-Epic (governs other epics' authoring)
**Tags:** tooling, spec, planning, bookkeep, markdown, yaml-frontmatter, schema, openspec, spec-kit, backlog-md

## Overview

Loop-lore has 281 epics and ~2100 tickets under `.plan/`. Each is hand-shaped prose —
no required frontmatter, no schema validator, no convergence loop, no per-change
artifact folder for multi-ticket features, and no acceptance-scenario grammar. The
existing `tickets/index.json` is regenerated by hand-edits and `bun run plan:sync:fix`.

This epic introduces a **unified `.md` spec framework** for `.plan/`, combining
OpenSpec's per-change artifact folder discipline with Backlog.md's mandatory YAML
frontmatter, with all bookkeep tooling bun-native and additive (no rewrites of
existing writers). The `tickets/index.json` is **reused** — `scripts/spec/*`
delegates the actual writes to the existing `scripts/worktree/sync.ts` writer so
loop-lore keeps one source of truth for that file.

> **Where this came from:** research + tooling survey + inventory living under
> `.plan/research-unified-spec-framework.md` + `.plan/research-unified-spec-framework.index.json`
> on the same worktree (branch `unified-spec-framework`).

## Goals

1. **Schema for specs** — every `.plan/` artifact (epic, feat, task, bug, idea, test, wire, perf, improve) carries a YAML frontmatter block with a canonical shape
2. **Validator** — `bun run scripts/spec/validate` lints `tickets/*.md` and `epics/*.md` against the schema; gateable from `bun run check`
3. **Rewriter for index.json** — `bun run scripts/spec/index-build` rewrites entries in `.plan/tickets/index.json` from frontmatter, delegating writes to `scripts/worktree/sync.ts` so the schema stays canonical
4. **Scaffolder** — `bun run scripts/spec/new <type> <slug>` creates a new ticket or epic with template frontmatter + sections
5. **Migration** — `bun run scripts/spec/migrate` (separate worktree, Phase B) backfills frontmatter on legacy artifacts, sets `_legacy: true`, and preserves all prose
6. **Convergence** — `bun run scripts/spec/converge <branch>` (Phase C) diffs merged branch commits vs the change's `Acceptance Scenarios`; emits `carryover.md`; pairs with `scripts/worktree/finalize` (opt-in hook)
7. **Archive** — `bun run scripts/spec/archive <change>` (Phase C) moves `changes/<name>/` to `changes/archive/<date>-<name>/`
8. **Single canonical status / priority / effort enums** — alias map for migration; v1 enums documented in `docs/spec/spec-schema.md`
9. **Acceptance-scenario grammar** — `### Scenario: <name>` + `**GIVEN** / **WHEN** / **THEN**` blocks; tools can parse; tests can target
10. **Per-change bundles** (optional) — `.plan/changes/<slug>/{proposal,design,specs/*,tasks,carryover}.md` for epic-scale features

## Acceptance Scenarios

### Scenario: New ticket passes validation
- **GIVEN** an agent scaffolds a new `TASK-<slug>.md` via `bun run scripts/spec/new task <slug>`
- **WHEN** the agent runs `bun run scripts/spec/validate`
- **THEN** the file passes (has YAML frontmatter with all required keys, has `## Summary`, `## Acceptance Scenarios`, `## Related`, `## Files`, `## Verification` sections)

### Scenario: Legacy ticket survives validation
- **GIVEN** a pre-existing ticket without frontmatter (existing 2000 tickets)
- **WHEN** `bun run scripts/spec/validate` runs (Phase B after migrate)
- **THEN** the ticket is reported once with `_legacy: true` and `legacy_aliases` populated; does not block CI

### Scenario: index.json stays canonical
- **GIVEN** `bun run scripts/spec/index-build` rewrites index entries from frontmatter
- **WHEN** the build completes
- **THEN** the `tickets/index.json` file still passes the existing `scripts/worktree/sync` parser; `git_issue` and `hash` fields untouched; only `updated` / `frontmatter` / `legacy_aliases` keys added

### Scenario: Convergence emits carryover
- **GIVEN** a merged worktree branch with `.plan/changes/<slug>/` and `## Acceptance Scenarios` blocks
- **WHEN** `bun run scripts/spec/converge <branch>` runs
- **THEN** an actionable `carryover.md` is written listing each scenario whose observable outcome was not found in `git log <base>..<branch>` or in tests; failure mode is loud (exit 1 if any scenario unchecked)

### Scenario: Migration preserves prose
- **GIVEN** `bun run scripts/spec/migrate` runs against a legacy ticket
- **WHEN** the migration completes
- **THEN** all prose below the frontmatter is byte-equal to the input; only the frontmatter block is added; status / priority / effort canonicalized via alias map; `_legacy: true` set

## Migration Strategy

- **Index.json** — REUSE not replace. `scripts/spec/index-build.ts` reads frontmatter and delegates writes to `scripts/worktree/sync.ts`. New fields (`updated`, `frontmatter`, `legacy_aliases`) are opt-in per entry; entries without them stay valid.
- **Tickets** — schema additive. Pre-existing tickets gain frontmatter with `_legacy: true` and continue to pass validation. New tickets are required to conform.
- **Epics** — same as tickets.
- **No data migration** — only metadata enrichment.
- **Phase boundaries** — A lands inside this worktree; B/C/D each open their own worktree and finalize via `scripts/worktree/finalize`.
