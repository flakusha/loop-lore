# TASK: Touch gestures (mobile interaction surface)

**Status:** In Progress
**Priority:** low
**Effort:** Medium
**Summary:** Wire touch gesture handling (tap, swipe, pinch, long-press) for mobile chat surfaces so the mobile frontend matches the desktop keyboard-driven experience. Sub-feature of `epic-accessibility-input`.
**Context:** Today the chat composer, message list, and chat sidebar rely on hover + keyboard. Mobile users get only the OS-default touch handling — no swipe-to-reply, no pinch-to-zoom the chat view, no long-press for message actions. `epic-accessibility-input` Phase 2 (touch gestures) was removed 2026-08-14 because the corresponding `.plan/tickets/TASK-touch-gestures.md` file was never created. This ticket re-files it so the epic's gap entry can be cleared.
**Acceptance Criteria:** [ ] Touch event handlers (`touchstart` / `touchmove` / `touchend`) registered on the chat composer, message list, and chat sidebar. (2026-10-25: message list done via `src/frontend/alpine/chat-touch-gestures.ts`; composer and sidebar outstanding — the sidebar keeps its own inline swipe. 2026-11-02: the message list also carries the pinch/pull detectors; still outstanding: the chat composer and the in-chat chat list panel (`src/components/chat/chat-list-panel.html`), which has no gesture surface. 2026-11-03: verified — the app-level `#layout-sidebar` keeps its own inline swipe (`src/frontend/alpine/sidebar.ts`, touch listeners on the branch rows), so no second implementation was added; the composer is a textarea whose swipe is a text-selection gesture (blocked by the selectable-text carve-out), so it stays open.) [ ] Swipe-right on a message bubbles a reply affordance; swipe-left marks read. (Delivered instead as the epic's canonical map: swipe-right → edit, swipe-left → archive-confirm dialog; no read-marking/reply affordance exists in the app.) [x] Long-press on a message opens the message-actions context menu. (2026-10-25, dispatched through the existing `openContextMenu` path.) [x] Pinch-to-zoom is limited to the chat scroll container (not the whole page) so the chat sidebar/composer stay anchored. (2026-11-03: the pinch drives the zoom of `#message-list` — the chat scroll container — through the CSS `zoom` property (`src/frontend/touch-zoom.ts`), clamped to [1, 2]; the sidebar and the composer sit outside the zoomed element and stay anchored. The zoom resets when the chat changes and when the list re-renders; the keyboard alternative is Ctrl+= / Ctrl+- / Ctrl+0.) [x] All gestures are no-op when the underlying touch is on a form input or selectable text. (2026-10-25: buttons/inputs/contenteditable carve-out done. 2026-11-02: the carve-out now covers the pinch and pull detectors too — a control-initiated pinch dispatches no action. 2026-11-03: the selectable-text half is done in the shared layer — `src/frontend/touch-session.ts` records the selection when the session starts and every detector asks `isBlocked` before firing, so a swipe, a pull, a pinch and a long press are all no-ops over a text selection, and a long press that itself starts a selection does not open the context menu.) [x] Unit tests cover each gesture's hit/miss conditions and the input-element carve-out. (`src/frontend/touch.test.ts`, `src/frontend/touch-session.test.ts`, `src/frontend/touch-zoom.test.ts`, `src/frontend/alpine/chat-touch-gestures.test.ts`; the control carve-out is asserted for the swipe, long-press, pull and pinch paths, the selectable-text carve-out for the swipe, pull and long-press paths, and the zoom for the pinch, both clamps, the reset and the keyboard shortcuts.) [ ] E2E test exercises a swipe on a real mobile viewport (`tests/e2e/browser/mobile-touch.browser.ts`). (Out of scope for the 2026-11-02 wave — still open.) [ ] `bun run check` green.
