## Acceptance Criteria

**Amendment (2026-11-12, sdcpp-discovery lane):** delivered as a config knob
over the existing failover chain rather than a `pickSdProvider` rewire —
`generation.imageRouting.comfyUiFirst` (default OFF = exactly the current
behavior; ON = healthy ComfyUI candidates order first, anything dead is
skipped by the walk's discovery gate with a structured reason and the chain
continues). The 2026-10-29 "ComfyUI-first, sdcpp opt-in fallback" semantics
hold through the knob; the engine and provider registry are untouched.

- [x] ComfyUI is the default route for `/image` requests when the operator
  opts in: `comfyUiFirstOrder` (`src/generation/image-engine/comfyui-first.ts`)
  puts ComfyUI candidates (stored setups + config providers) ahead of the
  chain inside `handleImageGeneration`; knob OFF returns the list untouched.
  No "complex vs simple" heuristic — ordering only, gating stays per-family.
- [x] sdcpp-down falls back to ComfyUI and vice versa: `generateImagesWithFailover`
  probe-gates BOTH families (`sdCppSkipAttempt` / `comfyUiSkipAttempt` against
  `/sdcpp/v1/capabilities` and `/system_stats`), records every skip/failure on
  the outcome's `attempts`, and answers 502 naming each reason when every
  candidate is skipped — never a silent stub.
- [x] Generated bytes persist as chat-linked assets on every family path
  (same `persistGeneratedImages` createAsset-link contract in
  `src/generation/image-gen-route.ts`).
- [x] Unit tests: purpose selection (listSdProviders, `sd-provider.test.ts`),
  per-family discovery gates incl. sd.cpp-down → ComfyUI fall-through and
  ComfyUI-down → fall-through with structured skip reasons
  (`image-engine/index.test.ts`), routing order under both knob states
  (`comfyui-first.test.ts`, `image-gen-route.test.ts`), no live server calls
  (fetch is stubbed).
