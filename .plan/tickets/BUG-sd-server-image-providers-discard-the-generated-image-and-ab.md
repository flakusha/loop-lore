# BUG: sd-server image providers discard the generated image and abort the job on one bad poll

**Status:** Not Started
**Priority:** Critical
**Effort:** Medium
**Epic:** epic-comfyui-plugin

**Summary:**

Two defects in the sd-server provider family.

1. The generated bytes are never persisted. Each family mints a fresh uid() and returns /api/assets/{id}/raw, but no createAsset call exists anywhere in src/image-edit/providers/sd-server-provider (grep: 0 matches), so every URL it hands back resolves to a row that was never inserted. The upstream bytes are unrecoverable.

Evidence read on dev:

- src/image-edit/providers/sd-server-provider/families.ts:72-80, :129-137, :174-182 — all three return a fresh uid-based id with no asset row.
- src/image-edit/providers/sd-server-provider/ops.ts:206-213 — upscale returns the same shape.

Compare src/image-edit/providers/comfyui-provider.ts, which persists and links each image immediately (recorded as a positive control in the review).

1. A single failed poll kills the job.
- src/image-edit/providers/sd-server-provider/families.ts:64-66 — if (!statusResult.ok) { throw new Error(...) } aborts on the first transient bad response instead of continuing to the next poll.

Source: .tmp/longcat/review-misc-services.md C1 and i6.
