# configs/assets — sample images for wardrobe / loadout / avatar features

This directory holds **procedural placeholder PNGs** that satisfy the
`(outfit × emotion)` variant key introduced by

# [`../../../.plan/epics/epic-wardrobe-avatar-variants.md`](../../../.plan/epics/epic-wardrobe-avatar-variants.md).

The placeholders are **not** intended as final art — they exist so that:

1. The config examples (`configs/templates/character.example.{yaml,toml}`,
   `configs/templates/avatar.example.{yaml,toml}`) reference real, in-repo
   image paths the renderer can resolve end-to-end.
2. Default-seeded characters (Elara, ARIA-7, Detective Morgan) carry
   `(outfit × emotion)` variants on first start so the wardrobe selection
   ladder has something to fall back to when the multi-avatar epic lands.
3. Tests asserting selection precedence have actual asset bytes to read.

## Long-term home

When the wardrobe epic lands and the multi-avatar pipeline generates
real art per `(outfit × emotion)` cell, the placeholders here become
**seed assets only** — the runtime renderer reads from the asset store
(DB-backed via the BLAKE3-dedup `asset_renditions` table per
`epic-asset-platform-capabilities.md` B1).

The intended migration is:

1. Wardrobe epic ships → the renderer resolves `(outfit, emotion)` via the
   selection ladder against the `asset_jobs` async store (B5).
2. Generated images persist under `data/assets/...` with the same
   `<character>/<outfit>/<emotion>.png` layout (renditions in
   `asset_renditions` table).
3. The PNGs in this directory remain the **fallback chain's terminal step**
   when no job output exists — `(outfit, emotion) → (outfit, neutral) →
   (default, emotion) → configs/assets/characters/<char>/default/happy.png`.

## How the placeholders are produced

The 33 PNGs were generated by a one-shot Bun script that emitted a minimal
PNG encoder (`IHDR` + deflate-compressed `IDAT` + `IEND`). Each cell is a
128×128 face silhouette with character-id hue + outfit-hash band. They are
intentionally **not** artistic — the goal is valid byte-for-byte PNGs that
exercise the variant-key path.

## Regenerating

Re-run the procedural generator from the worktree root:

```bash
bun run scripts/gen-wardrobe-samples.ts    # not yet a script — see worktree plan-wardrobe-loadouts
```

(When the wardrobe epic lands, this becomes `bun run assets:gen-samples`.)

## Replacing with real art

To swap in real generated/stock images:

1. Drop a 256×256 (or larger) PNG into the corresponding cell path.
2. Keep the file name (`<emotion>.png`) so the variant-key resolution
   keeps working.
3. Optionally add `thumb_l.png` / `lqip.png` renditions under the same
   cell — the B1 epic wires those into `asset_renditions`.
